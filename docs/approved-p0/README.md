## What changed

- Pure-black neutral conversation shell; 256px desktop sidebar, tablet drawer, readable 16px conversation/input, 44px controls, stacked phone financial metrics, one demo disclosure and preview-first plans.
- Per-chat drafts live only in memory, including navigation to and from payments. Prompts do not overwrite a draft. Back/Forward resolves chat URLs. Reload/switching clears account authority. Explicit sign-out clears private drafts across both workspaces.
- Immediate pending message and neutral working state; no forced focus on completion. Readers retain their scroll position and selected control, with a Latest response action when needed. An uncertain POST outcome requires checking saved turns before retry. History refresh failure keeps the saved reply. Session expiry retains only the current unsent text and permits sign-in without auto-send.
- Additive v1 presentation from the same validated financial results: exact signed amounts, account/date/filter/status scope, coverage, unique candidate identities/actions and complete evidence/original response. Unsupported or malformed legacy payloads retain the entire original text. There is no client money calculation.
- A real `narrate` task through the existing configured Gemini/OpenAI adapter, within the existing six-call/60-second limits. Accepted prose, cards and evidence describe one rechecked snapshot and persist together. Failed narration has an explicit factual-fallback label; revoked/stale facts cannot fall back.
- Existing payment editor, beneficiary verification, review digest, password approval, one-use submission, status checks and emergency stop are retained. Return links carry only the opaque originating chat ID. During batch review the payment composer collapses to a return control.
- Gerald's existing browser voice implementation is preserved. No second recorder, provider, upload endpoint or capture flow was introduced. It still fills one editable payment text draft and uses its existing submit path. Additional lifecycle guards reject failed/late results after submit/navigation/sign-out, and appending preserves typed whitespace. Unsupported browser controls are hidden. The new financial-chat composer has no microphone until a real shared integration is available; its optional toolbar slot is reserved.

## Narration boundary and limitations

Financial narration uses **constrained prose authoring**, rather than a second model acting as factual judge. The configured model receives the scrubbed question, validated result snapshots/references, backend-owned value slots, required limitations and a whole-sentence claim grammar. It chooses supported observations, wording, order and paragraphs. The deterministic validator checks every sentence/reference, supported comparison direction, permitted value slot and required material limitation before inserting exact values. Arbitrary free-form financial assertions, literal model numbers, invented entities/sources, balance/credit claims and unsupported comparisons fail closed.

This conservative grammar deliberately limits expressive range. Unrecognized phrasing, exhausted budgets, provider failures or unsupported result types can produce a factual fallback. It does not promise unrestricted personalized advice or infer causes/categories/trends absent from the facts. The fixture proves the stage is invoked and accepted; **live provider quality and acceptance are unverified**. `genuine-narration.json` records `MODEL_NOT_CONFIGURED`, zero calls and no passing cases. The original genuine 12-case verifier and its acceptance predicates are unchanged; a separate narration gate is supplied.
