## Limits and operational requirements

- No Paystack account or production credentials were accessed, no real financial transaction was initiated, and no live payment flags were enabled. Provider/account integration remains unverified.
- Concurrency was tested against the existing embedded PostgreSQL/CAS implementation; disk persistence was tested across sequential process restarts. A managed PostgreSQL deployment with multiple application processes was not available for testing.
- Run and monitor the existing `npm run payments:reconcile` scheduler every minute. Work retries GET verification only. Missing webhook delivery still requires operational review of older successful transfers; this repair recovers received events, not events never received.
- An interrupted/uncertain OTP claim stays consumed even if interruption preceded the actual provider request. Resolve the reference and investigate; the application does not authorize a replacement transfer or another finalization attempt.
- Missing/conflicting recipient identity remains unverified. Provider responses containing only a numeric recipient ID require a previously stored approved ID. Old OTP/receipt recovery depends on retained audit evidence.
- Existing singleton JSONB storage, growing audit history, single-operator authentication and database-administrator audit mutability remain documented prototype limits. These repairs do not replace the broader independent security review or `LIVE_READINESS.md` requirements.
